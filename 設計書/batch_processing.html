4. バッチ処理設計・プログラム実装仕様

GitHub Actionsを用いて定期実行するPythonスクリプトの詳細な実装仕様を定義する。この仕様に従えば、誰でも同じ結果を得るバッチプログラムを作成できる。

4.1 スケジュール定義

  • ① JPX会社情報巡回: 平日 17:00 (新規上場、上場廃止、社名変更の検知)
  • ② 日次株価収集: 平日 18:00 (直近3日分の差分を取得し、ストップ高安を判定)
  • ③ 週次信用残高収集: 毎週火曜 19:00 (JPXからCSVを取得)
  • ④ 優待・決算巡回: 毎週日曜 02:00
  • ⑤ ローカルバックアップ＆データパージ: 毎週日曜 03:00

4.2 株価取得処理 (yfinanceベース) 詳細仕様

対象ファイル: fetch_stock_prices.py

【実装必須要件】
  • 銘柄の指定: 日本株であるため、必ず取得対象の銘柄コードの末尾に .T を付与して yf.Ticker("7203.T") のように呼び出すこと。
  • 株式分割の対応: yfinanceが返すOpen, High, Low, Closeは全て「分割・併合調整済み」である。DB登録時は close_price と adjusted_close の両方に同じ値をセットしてよい。
  • 前日比の計算: 指定した日数(例:3日)の「前日比」を計算するため、APIへは period=4d のように「+1日分」のリクエストを送り、Pandasの shift(1) で差分を計算した後、直近3日分に tail(3) で絞り込むこと。

ストップ高・安フラグの判定ロジックについて

現在のプロトタイプではプレースホルダー（False固定）としているが、本格実装時は前日の close_price を基準とした「制限値幅表」に基づく判定関数を作成し、本日の high_price や low_price がそれに到達しているかで判定を行う。

4.3 その他のデータ取得仕様

  • 信用取引残高: JPX公式の「二市場信用取引残高」ページよりエクセル/CSVを取得する。ファイル内の「基準日」列（通常は金曜日）を抽出し、DBの report_date に設定すること。発表日（火曜日）ではない点に注意。
  • 優待・決算日: Yahoo!ファイナンス、または「みんかぶ」のスクレイピング。優待内容は自然言語のため、HTMLテキストから不要なタグを取り除いた純粋なテキストを benefit_summary に格納し、正規表現を用いて「最低必要株数(株)」の数値を抽出し min_shares に格納する。

4.4 エラーリカバリーと通知仕様

  • エラーリトライ: WebスクレイピングやAPI呼び出し部分はネットワークエラーが頻出するため、tenacity 等のライブラリを用いて自動で3回のリトライ処理（Exponential Backoff）を組み込むこと。
  • サイレント実行: 夜間バッチでエラーが発生しても、Webhook経由での即時LINE通知は行わない（ログ出力のみ）。
  • サマリー通知: 翌朝07:00に別のジョブを起動し、ログを解析して「取得成功〇〇件、エラー〇〇件」というサマリー1通のみをLINEへ通知する。
  • 欠損データの補完: 株価バッチは常に「直近3日分」を取得するため、前日バッチがダウンしても翌日バッチが成功すれば自動的に欠損データが補完される設計（冪等性の確保）とする。

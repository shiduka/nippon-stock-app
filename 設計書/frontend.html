5. 画面・UI設計 (Streamlit)

スマートフォンでの片手操作を前提とした1カラムレイアウトを採用。上部の4つのタブ（またはセレクトボックス）で画面を切り替える。

5.1 画面タブ構成

  1. 【個別銘柄詳細】: 検索バー（銘柄コード、または企業名の一部で曖昧検索）。直近株価、イベント情報（次回決算日）、インタラクティブチャート（ローソク足、移動平均、出来高、信用残高推移）、優待詳細を縦スクロールで表示。
  2. 【優待スクリーナー】: 権利確定月（マルチセレクト）、ジャンル、最低投資金額などのフィルターを用いて、テーブル形式で優待銘柄を検索。
  3. 【スマート・スクリーナー】: 事前定義されたプリセット条件（例:「🚀 本日のストップ高」「⚡ 信用倍率1倍割れの好取組」）をドロップダウンから選ぶだけで、結果を即座に表示。
  4. 【システム管理】: バッチの直近ステータス確認、手動リカバリー実行ボタン、ローカル分析用Parquetファイルのダウンロード用リンク。

5.2 パフォーマンスとDB負荷分散設計 (重要仕様)

Streamlit Community Cloudはメモリ上限（約1GB）が厳しく、全銘柄データをPandasに読み込んでメモリ上でフィルタリングを行うとアプリがクラッシュする。

実装ルール（Pushdown）:
  • SELECT * FROM daily_stock_prices のような全件取得は厳禁とする。
  • 「スマート・スクリーナー」などの複雑な条件検索は、すべて Supabase の PostgreSQL 側で実行させる。必要に応じてSQLのViewや、Stored Procedure (RPC) を定義して呼び出すこと。
  • Streamlitアプリ側は、SQLで LIMIT 100 など絞り込まれた上位の軽量な結果セットのみを受け取り、画面への描画（レンダリング）に専念する「UI層」として振る舞うこと。

5.3 スクリーニング用プリセット定義 (Python)

タブ3で使用する検索条件は、後から追加しやすいようにPythonの辞書形式（設定ファイル）で管理する。


SCREENING_PRESETS = {
    "signal_stop_high": {
        "title": "🚀 本日のストップ高",
        "sql_where_clause": "is_stop_high = TRUE AND status = 'ACTIVE'"
    },
    "margin_squeeze_candidates": {
        "title": "⚡ 信用倍率1倍割れの踏み上げ候補",
        "sql_where_clause": "margin_ratio < 1.0 AND margin_sell_volume > 50000"
    },
    "high_dividend": {
        "title": "💰 高配当 (4%以上) ＆ 今月決算",
        "sql_where_clause": "dividend_yield >= 4.0 AND fiscal_month = EXTRACT(MONTH FROM CURRENT_DATE)"
    }
}

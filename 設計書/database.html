3. データベース詳細設計 (テーブル定義)

将来的な項目追加を見据え、各テーブルに extra_data (JSONB / TEXT) を用意し、デフォルトは '{}'::jsonb とする。また、企業マスターを基点とした ON DELETE CASCADE を設定し、データ整合性を担保する。

3.1 companies (企業マスターテーブル)

カラム名データ型PK/FK説明
ticker_symbolVARCHAR(10)PK銘柄コード
company_nameVARCHAR(255)最新の企業名
marketVARCHAR(50)市場区分（プライム等）
sector_33VARCHAR(100)33業種区分
statusVARCHAR(20)'ACTIVE' (上場中) / 'DELISTED' (上場廃止)
delisted_dateDATE上場廃止日
fiscal_monthSMALLINT本決算月 (1〜12)
next_earnings_dateDATE次回決算発表予定日
dividend_yieldDOUBLE PRECISION予想配当利回り(%)
extra_dataJSONB自由拡張枠

3.3 daily_stock_prices (日次株価テーブル)

カラム名データ型PK/FK説明
ticker_symbolVARCHAR(10)PK1/FK (CASCADE)銘柄コード
trade_dateDATEPK2取引日付
open_priceDOUBLE PRECISION始値
high_priceDOUBLE PRECISION高値
low_priceDOUBLE PRECISION安値
close_priceDOUBLE PRECISION終値
adjusted_closeDOUBLE PRECISION調整後終値（株式分割対応用。yfinanceの場合はcloseと同値）
volumeBIGINT出来高
price_changeDOUBLE PRECISION前日比（騰落幅）
is_stop_highBOOLEANストップ高フラグ (Default: false)
is_stop_lowBOOLEANストップ安フラグ (Default: false)
extra_dataJSONB自由拡張枠
インデックス設計: Streamlitの動作を高速化するため、以下を作成する。 CREATE INDEX idx_daily_stock_prices_date ON daily_stock_prices(trade_date DESC); CREATE INDEX idx_daily_stock_prices_stop_high ON daily_stock_prices(is_stop_high) WHERE is_stop_high = TRUE;

3.5 margin_balances (信用取引残高テーブル)

カラム名データ型PK/FK説明
ticker_symbolVARCHAR(10)PK1/FK (CASCADE)銘柄コード
report_dateDATEPK2基準日（※必ず集計基準日である金曜日の日付を入れる）
margin_buy_volumeBIGINT信用買い残（株数）
margin_sell_volumeBIGINT信用売り残（株数）
margin_ratioDOUBLE PRECISION信用倍率 (買い残 ÷ 売り残)
基準日の取り扱い注意:
信用残高はJPXより「翌週の火曜日」に発表されるが、DBの report_date には実際の集計時点である「直近の金曜日」の日付を登録する。これにより、株価チャートと重ね合わせた際の時間軸のズレを防ぐ。

データ保持・パージ戦略 (無料枠対応)

Supabaseの容量上限（約500MB）を回避するため、ホットデータとコールドデータを分離する。

  • ホットデータ (Supabase): 過去2年分の daily_stock_prices を保持。
  • コールドデータ (ローカル/Parquet): 毎週日曜日の夜間バッチにて、全履歴をParquetファイルに出力しバックアップ。
  • データパージ: バックアップ完了後、Supabase上から trade_date < CURRENT_DATE - INTERVAL '2 years' のレコードを DELETE する。
